# 1.8.0 单注差额与奖金构成

本轮对照持续复盘里已经展示的并集命中、见奖和“回本”，核对它们能不能回答“为什么没有头奖注”以及“回到成本是不是来自一二等奖”。正式 `data/` 仍只有 `.gitkeep`，没有可以统计实际成绩的大乐透档案。下面的数字、截图和导出都来自临时数据库里的合成票组，不代表真实命中或收益。未部署生产服务。

原复盘已经写明并集命中不等于单注命中，稳定性里的回本则是净额不小于 0。净额回到成本时，奖金可能全部来自三等奖及以后的固定奖；一二等奖金额未公布时，如果把未知当成 0，回撤和回本都会失真。

## 距头奖拆成池外和未集中

对每个合格原始方案，沿用已经核算的逐注命中，不重新选号。单注距头奖的差是 `(5 - 前区命中) + (2 - 后区命中)`。各区再拆成两部分，并且必须加总相等，对不上就拒绝整份复盘：

- 池外不足：开奖号里没有进入该方案号码并集的个数。这些号不会因为重排现有票而出现。
- 未集中：开奖号已经在并集里，但没有出现在该区命中最多的那一注上。

两区各自的最高命中不一定属于同一注。最近单注单独列出同一注上的前区、后区和示例号码。两区并集都盖住开奖号、却没有任何一注是 5+2 时，记为“两区都覆盖但无头奖注”，不把它算成头奖。

待开奖的命中、差距和头奖注数保持未知。

## 浮动奖回本和固定奖补足分开

一二等奖金额算浮动奖，三等奖及以后算固定奖，直接使用原结算金额。追加若已经并入一二等奖公布额，仍留在浮动奖里。

- 浮动奖回本：浮动奖本身不少于本期成本。
- 固定奖补足：总奖金回到成本，但浮动奖不够。只中固定奖、甚至因此净额不小于 0，也不算浮动奖回本。
- 任一必要金额未知时，这两项保持未知，不把未知记成 0，也不把部分已知金额当成整期合计。

浮动奖与固定奖之和必须等于原结算奖金，否则拒绝发布这张表。原稳定性表里的“回本”仍是净额不小于 0，页面注明其中包含只靠固定奖补足的期。

## 回撤和连亏

最大回撤沿实际留档的已开奖净额计算，起点为 0，缺档不补零。已开奖期里只要有一期金额未知，整段回撤就是未知。

连亏只计算净额小于 0 的同年连续期。金额未知或期号不连续会打断，并标明这只是已知片段。没有完整金额时，连亏不是 0。

请求的复盘窗口和实际列入期数分开显示。列入期数包含缺档和待开奖，不能把它当成已开奖样本数。

## 兼容与验证

选号仍为 `dlt-plan-v3`，无需数据库迁移。复盘报告仍是版本 2，只增加每条档案的 `hit_gap` 和每个方案的 `hit_review`。完整数据导出仍为版本 4。旧报告没有这些字段时，页面说明差额不可用，不显示 0。

“导出差额证据”是版本 1 的诊断 JSON，包含当前复盘摘要引用、各方案汇总和逐期差额，不包含重新生成的号码。

80 项 Rust 全目标测试、49 项 JavaScript 检查、格式检查、Clippy 及 Release 构建通过。新增检查覆盖：池外与未集中恒等、并集盖住两区但没有头奖注、固定奖回到成本不算浮动奖回本、一二等奖金额缺失时回撤和回本未知、2019 规则的四等奖仍归固定奖、期号缺口打断连亏、空样本和待开奖不记 0，以及拆分对不上时拒绝报告。

`scripts/verify-hit-gap.cjs` 使用发布二进制和临时库实际归档两期，其中一期合成开奖且不公布一二等奖。浏览器确认头奖方案的浮动奖和回撤为待核实、另一期待开奖、差额恒等、各方案回本分类与接口一致。这组合成数据里有一个方案只靠固定奖回到成本，页面计为固定奖补足，浮动奖回本为 0。七个页签在 1440px 和 375px 下没有页面横向溢出，也没有脚本错误。读取前后档案、开奖、推荐和审计计数一致。

```bash
cargo fmt --check
cargo test --locked --all-targets
cargo clippy --locked --all-targets -- -D warnings
node --test tests/*.cjs
cargo build --release --locked
# 需本机已有 Playwright 与 Chromium
PLAYWRIGHT_MODULE=/path/to/playwright node scripts/verify-hit-gap.cjs \
  --binary target/release/lottery-dlt --browser /path/to/chrome
```
