# 1.7.1 读取恢复与复盘状态修正

本轮参照本机 `lottery-k8/docs/review-20261028.md` 的请求故障复盘，以及 `review-20261029.md` 对缺失、待开奖和实际留档的区分，核对当前项目。大乐透的读取接口没有快乐8兼容层的单一计算通道限制，因此继续并行读取，修复本项目实际存在的等待和状态问题。

正式 `data/` 仍只有 `.gitkeep`，没有可以统计实际成绩的大乐透档案。本轮不提供真实命中或收益结论；所有测试档案、请求故障和截图均来自临时数据库，未部署生产服务。

## 已复现的问题

使用修改前的1.7.0发布程序进行浏览器检查，确认：

- 运行状态接口一直不返回时，等待8.5秒后仍停在初始化，选号表单没有出现。
- 连续两次刷新，较早请求最后返回时会覆盖较新结果。
- 空库概况接口和个人方案页显示零净收益，而持续复盘已将此情形视为未知。

基线记录位于 `test-results/read-recovery-baseline-1.7.0/baseline.json`。后续浏览器检查还发现：对奖列表读取失败后，页面虽然出现重试入口，刷新按钮的回调仍会弹出“已复算成功”。本轮同时修正这一提示。

## 读取有等待上限，错误可恢复

新增内置 `transport.js`，统一读取响应与错误处理：

| 读取类型 | 等待上限 |
| --- | ---: |
| 销售日程、运行状态 | 5秒 |
| 普通读取，包括概况、配置和档案列表 | 15秒 |
| 持续复盘、完整导出、单个后台任务及结果 | 60秒 |

上限覆盖连接和响应正文读取；只收到响应头但正文停住，也会进入错误路径并中止浏览器请求。用户可通过现有重试按钮恢复。收到代理HTML、损坏JSON或空值响应时，明确显示读取错误，不将其当作有效报告。

日程或运行状态超时后，核心概况和配置仍可用于打开页面；状态不明时保持保存按钮禁用，重试成功后恢复正常校验。迟到的辅助响应不会自行消除错误。核心概况或配置失败时立即返回错误，无需等辅助接口结束。

本次没有为保存、导入、配置更新和任务提交增加浏览器超时，也没有自动重发请求。写入响应中断或无法解析时说明结果尚未确认，提示先核对记录或状态；服务端返回的明确业务错误仍按原信息展示。中止读取并不保证服务器已停止处理该读取。

![辅助状态超时后仍可使用页面，并可重试](../test-results/read-recovery-1.7.1/01-auxiliary-timeout-desktop.png)

## 新状态不会被旧刷新覆盖

概况刷新带递增请求编号，仅接受最近一次刷新；旧成功响应和旧错误都被忽略。成功保存主种子也会使此前的刷新失效，避免旧配置重新进入当前页面。

档案页与报告继续使用原有的导航和请求编号保护。读取失败后，期号筛选和复盘窗口保留，重试只读原票。对奖刷新只有在当前档案列表确实渲染成功后才提示成功；超时或切页后的旧请求不会给出成功提示。

![档案读取超时保留真实错误及重试入口](../test-results/read-recovery-1.7.1/02-record-timeout-mobile.png)

复盘报告发生故障时，原始推荐票组仍可展开，报告区域提供独立重试。

![报告收到无效JSON时可独立重试](../test-results/read-recovery-1.7.1/03-invalid-report-mobile.png)

## 空样本收益统一为未知

概况接口 `settled_prize_fen`、`settled_net_fen` 和个人／推荐列表页汇总，现在都要求至少一个已开奖方案才能产生完整金额。空库、当前筛选无已开奖档案、只有待开奖档案时显示待核实，并说明尚无收益结果。

已有开奖且确实未中奖时，奖金仍为0，净额仍扣除实际成本；有中奖但缺少公告奖额时仍返回未知。未更改逐注奖表、选号参数、生成规则、推荐预设或已保存票组。

![待开奖方案的净收益保持未知](../test-results/read-recovery-1.7.1/04-pending-summary-mobile.png)

## 验证与兼容

本轮增加请求正文悬挂、超时中止、成功后清理定时器、异常JSON、写入不重发、核心失败及时返回，以及空／待开奖／真实零奖金的检查。浏览器脚本 `scripts/verify-read-recovery.cjs` 检查真实5秒辅助超时，并用浏览器时钟推进15秒和60秒的读取期限；测试未缩短生产代码的超时参数。

浏览器检查还覆盖先后刷新乱序、保存新种子后的迟到配置、对奖失败无成功提示、期号与窗口保留、原始5组推荐可见、切页后忽略旧错误、七页签桌面和375px手机布局。故障恢复前后，对比原始档案、推荐清单、开奖、配置、日程、评分证据和审计计数，确认读取没有写入数据库。唯一主动修改种子的案例也只在临时库中执行。

68项Rust全目标测试、48项JavaScript检查、格式检查、Clippy及Release构建通过。发布二进制通过六套浏览器验收：`verify-read-recovery.cjs`、`verify-applicability.cjs`、`verify-usability.cjs`、`verify-replacements.cjs`、`verify-k8-alignment.cjs`、`verify-score-evidence.cjs`。无浏览器脚本错误；覆盖七页签的桌面及375px手机检查，无页面横向溢出。原评分、换号净变化、缺失奖金、导出、草稿及原始票组回归通过。

选号仍为 `dlt-plan-v3`，无需数据库迁移；完整数据导出版本4、号码池版本3、复盘报告版本2均保持兼容。截图和机器验收记录位于对应的 `test-results/*-1.7.1/`，按项目规则作为本地验收产物忽略。
