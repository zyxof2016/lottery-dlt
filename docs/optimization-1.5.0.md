# 1.5.0 选号依据、集合诊断与留档稳定性

参照本机 `lottery-k8/docs/review-20261026.md` 中的原始分值、等分破局、受控集合对照和单期奖金集中度检查，适配大乐透的前后双区。以下浏览器截图和数值均来自独立临时数据库的合成数据，用于功能验收，不代表实际推荐成绩。

## 原始选号依据

在方案预览点击“查看选号依据”，或在个人／推荐档案点击“原始选号依据”，可查看前区35个及后区12个号码的原始顺序、分值、同分名次区间及人数、窗口内次数／遗漏、候选池、最终入票及胆码状态。候选截取跨越同分组时，单独显示截取边界。

热号分值为出现次数，冷号为出现次数的相反数，遗漏为当前遗漏；窗口内未出现的号码仍标注遗漏下界。分值是历史启发式依据，没有校准成中奖概率。同分名次使用原生成器的固定种子破局，靠前不表示分值更高。随机、均衡覆盖和结构选号没有历史评分，显示“未使用历史评分”，不伪造零分或判成等分模型。

新保存的原始票组与选号依据在同一SQLite事务中写入；依据单独摘要校验并追加审计事件，绑定原方案编号、历史摘要、数据截止和生成规则。读取校验全部号码、分值顺序、同分区间、候选边界和入票状态。修改种子、导入开奖和补齐奖金只改变当前预览或对奖结果，不重写原依据。旧档案缺少评分时显示“未记录”，重复保存或整期归档复用时也不回填。

开奖后，原候选池按已入票、入池未构票、池外分解命中；三者互斥，合计为当期前区5个、后区2个开奖号。待开奖显示未知。

## 号码池受控对照

保留原来按来源计频的默认视图，新增两个可组合开关，均只改变诊断视图：

- **按本区号码内容去重计频**：前后区分别合并同内容池，每组一票。频率分母使用本区实际有效计票池数，仍保留每个原始来源及分组关系。
- **分别排除确认等分的排名选号来源**：仅排除有原档案评分证据、全区同分且候选池按排名截取的来源。前区等分不会连带排除后区；自选候选池、手动输入、未使用历史评分及旧评分未知的来源继续保留。

结果展示有效计票池数、活动来源数、排除数量及证据未知数量。排除全部来源时，本区交集与并集为空，不产生除零频率；待开奖命中仍未知。已有参考池、不同门槛删号及丢失命中对照继续可用。

开关与所选池保存在当前标签页会话中，刷新可恢复。读取同编号且同号码的原档案时，只刷新评分摘要，不修改已选池号码。JSON保留所有原始池、排除理由、内容分组和阈值曲线；CSV保留当前诊断视图全部并集行、原始来源及有效分母，不受显示门槛影响。两区均无有效行时停用CSV导出，JSON仍可导出原选择。

## 实际留档稳定性

“每期推荐与复盘”新增可直接跳转的稳定性区域，按原实际推荐方案分别统计：已开奖／奖额完整期、前后区并集命中范围、中奖期、已知盈利／回本期、最长连续未见奖、最大单期奖金占比、原评分确认等分期及依据缺档期，并提供逐期原票链接和金额。

沿用实际推荐纳入校验，未纳入档案不参与这些指标。待开奖不算零分；连期只认同年连续期序，缺档或跨年中断。盈利和回本仅统计奖额完整子集，尚无可核实金额时显示未知。任一已开奖档案的奖额缺失时，奖金集中度为未知；总奖金为零时不计算比例。覆盖、短期盈利或单期大奖均不用于切换默认策略，也不表示未来优势。

## 兼容与接口

版本1.5.0沿用 `dlt-plan-v3`。通过旧版1.4.0发布二进制捕获的14组单式、复式、胆拖结果对照，新增依据采集前后的完整方案JSON、号码、编号均一致。`Plan` 和 `SavedPlan` 的结构及原摘要保持兼容。

数据库首次打开自动添加 `selection_evidence` 表，既有档案不补造评分；SQLite备份与恢复校验包含此表。完整数据导出的 `schema_version` 升为4，增加按方案编号索引的 `selection_evidence`。号码池诊断JSON版本升为3，增加诊断选项、按区有效分母、内容分组及排除来源；原有字段继续保留。

- `POST /api/plans/explain`：传入 `request` 和 `preview_id`，遵守现有管理员写接口认证，只读解释当前预览；种子或历史已变化、预览不匹配时拒绝。
- `GET /api/records/{id}/evidence`：读取并校验原档案依据及当前开奖分解，旧档案返回 `not_recorded`；不存在返回404，摘要等校验失败返回409。
- 档案与推荐分页响应增加 `selection_evidence` 摘要映射；实际复盘的各方案增加 `stability` 及逐期证据。

同时修正查票时个人与推荐列表混用可能读取旧对奖结果的问题：按当前页的原档案展开、复制和导出。

## 验收记录

60项Rust全目标测试、32项JavaScript检查、Clippy、格式检查及Release构建通过。新增覆盖包括14组旧版方案一致性、双区等分与截取边界、未评分／自选池、旧档不回填、同事务回滚、种子变化后原证据不变、备份恢复、损坏拒绝、接口认证及过期预览；集合检查覆盖按区去重、正确分母、排空来源、未知值和会话恢复。

三套Chromium验收使用发布二进制、临时数据库及 `/dlt` 路径：

- `scripts/verify-score-evidence.cjs`：实际点击预览和归档依据、全部47个号码、手机表格、诊断开关、去重、自选池保留、JSON下载、刷新恢复、缺失奖额与集中度；只读操作前后原档案、评分、开奖、配置、推荐及审计数相同。
- `scripts/verify-k8-alignment.cjs`：复盘、预算增量、号码池、CSV／JSON、复制失败及故障恢复回归。
- `scripts/verify-usability.cjs`：参数、费用、生成／保存、直达原票、筛选、大票组复制及错误恢复回归。

后两套均检查1440px桌面及375px手机全部七页签；无脚本错误或页面横向溢出。截图及机器报告分别保存在 `test-results/score-evidence-1.5.0/`、`test-results/k8-alignment-1.5.0/`、`test-results/usability-1.5.0/`，是按项目规则忽略的本地验收产物。本次只修改本地项目，未部署；正式 `data/` 目录未写入测试数据。
