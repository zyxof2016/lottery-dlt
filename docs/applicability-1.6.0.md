# 1.6.0 应用性分析与使用流程优化

本轮针对本地项目的“首次打开 → 设置与暂存 → 保存 → 查票与故障恢复”开展体验检查并修改。使用 Product Design audit 流程，先在独立临时数据库捕获旧版1.5.0，再检查截图与交互；实现后重新运行相同流程，并注入接口和浏览器存储故障。以下号码均为合成验收票组，截图中的日期和金额不代表真实推荐成绩。

## 应用性结论

当前项目适合管理原始票组、计算成本、按实际开奖对奖、追溯生成依据和进行历史对照。生成、保存及开奖核验已经能衔接；原票摘要、旧评分未知和待核实奖金也有明确边界。

实际使用的主要障碍是准备状态不够集中、未保存输入容易丢失，以及辅助数据故障影响核心操作。本轮优先改善这些环节。历史评分与短期复盘不能证明未来预测优势；此轮改动也不改变选号算法、默认策略或原档案。

## 1. 首次启用：补齐下一步指引

旧版首次打开能诚实提示“无开奖数据”和“需要管理员访问”，但登录、数据准备及目标期号的入口分散，停售要求需要到设置中自行查找。

现在生成页集中展示权限、开奖数据、目标与截止时间三个准备事项，提供可操作入口及“前往选号参数”。生成页不再重复堆叠顶部同类通知；其它页面仍保留数据与访问提示。存在开奖缓存且没有阻断性准备事项时默认折叠准备说明；空库不再展示一张没有号码的最近开奖卡片。

未填写令牌、期号格式不完整、目标期不晚于已知开奖、历史实验缺少数据时，在提交前说明原因和下一步；随机、均衡仍可在无历史数据时使用。管理员认证及参数有效性最终由服务端校验。

期号快捷填入只使用未来30天内、最近两小时核实且未过截止的日程，不自行推算下一期。严格日程模式下，没有匹配有效日程时可预览，保存按钮说明阻断原因并引导核实。日程或运行状态读取失败时，也先暂停保存，避免把未知状态显示成允许手填。

## 2. 设置与暂存：修复切页丢输入

基线实际填写名称和截止时间后，切到“我的方案”再返回生成页，两项均被清空。机器报告 `draft_preserved_on_navigation=false`，截图可见相同期票组的两个输入变空。

现在参数、名称和截止时间随输入暂存在当前标签页的 `sessionStorage`，按应用路径区分；同页切换后继续编辑。刷新只恢复输入，并明确要求重新生成、确认后才能保存，既不持久化未确认的预览，也不把草稿当作已留档票组。新的目标期会清空上一期的名称和截止时间。

草稿采用版本化结构及字段白名单，不包含完整票组、原方案编号或管理员令牌；自选池仍作为选号参数保留。损坏、超大或格式无效的缓存拒绝恢复；存储不可写时给出可见提示，保留当前内存输入。清除草稿只处理当前页面缓存，不删除原档案。重复的草稿状态文字不反复写入 live region，减少辅助阅读干扰。

保存完成即清除对应草稿。延迟返回的旧保存请求，只有在当前仍为对应生成版本时才清除草稿，避免擦掉用户随后填写的另一份方案。

![优化后：同样切页，名称和截止时间仍保留](../test-results/applicability-1.6.0/03-returned-draft-mobile.png)

## 3. 保存与异常恢复：区分原票结果和辅助刷新

基线向运行状态接口注入503后，整个应用停在“暂时无法读取数据”，导航与选号表单均未出现；`optional_failure_isolated=false`。这使非核心状态故障放大为整体不可用。

现在概况、配置与辅助状态分别处理：概况／配置仍须成功读取；销售日程和运行状态失败则明确标为未知、提供重试，已有档案可继续浏览，生成预览可继续进行。运行状态未读取时，不显示自动归档的默认设置。页面主要数据失败时，提供“重试当前页面”，并保留期号与开奖状态等筛选。

静态检查还发现，原保存逻辑在确认接口成功后继续等待概况刷新，后者失败会进入通用报错。现在先展示原档案保存成功及查票入口，再单独刷新概况；后续失败会明确显示“保存已成功，概况暂未刷新”，不会再次显示保存按钮或要求重存。

![优化后：状态失败可重试，导航与主要流程仍可用](../test-results/applicability-1.6.0/04-optional-failure-mobile.png)

![保存成功后模拟概况失败，仍保留成功确认与原档案链接](../test-results/applicability-1.6.0/05-save-success-refresh-failed-mobile.png)

## 4. 查票与复盘：保持原票与已有功能

验收实际保存25注，随后通过成功链接展开全部原始票组，逐项与生成结果核对。重试、草稿恢复、清除缓存及延迟重复保存均未新增另一份票组；首次保存的编号和号码保持一致。

已有费用估算、20注以上预览展开、完整复制、期号与开奖状态筛选、原评分、集合诊断、奖金缺失及补齐、预算增量和稳定性继续通过回归。手机保存按钮在预览顶部约375px处，仍在812px视口内；前后截图因提示文字换行而略有高度差异。

## 验收与边界

- Rust全目标60项测试、JavaScript37项检查、Clippy、格式检查及Release构建通过。
- 新增 `tests/workflow.cjs` 验证草稿白名单与损坏拒绝、权限／历史／目标期前置判断、有效日程筛选，以及辅助接口失败不冒充默认状态。
- `scripts/verify-applicability.cjs` 在发布二进制上实际完成首次登录、生成、填写、切页保留、刷新后重生成、辅助接口故障／重试、保存成功后的概况故障、原票读取、列表失败后带筛选重试、清除草稿、严格日程、有效日程快捷填入、损坏／不可写存储，以及旧保存延迟返回时保留新草稿。
- 与 `verify-usability.cjs`、`verify-k8-alignment.cjs`、`verify-score-evidence.cjs` 四套浏览器流程共同验证；前两套既有流程和本轮流程检查1440px桌面与375px手机全部七页签。无脚本错误或页面横向溢出。
- 生成规则仍为 `dlt-plan-v3`；没有改变数据库结构、完整导出版本或档案内容。新增静态 `workflow.js` 与其它网页资源一起嵌入二进制。
- 基线及优化后产物分别位于 `test-results/workflow-before/` 和 `test-results/applicability-1.6.0/`，其余报告在对应的 `*-1.6.0/` 目录；均为按项目规则忽略的本地文件。测试数据只写入可清理的临时数据库。

截图支持视觉和状态判断；故障、存储、原票一致性等结论由实际浏览器操作及接口对照补充。未进行屏幕阅读器、移动实体设备或完整无障碍合规认证。生产网络下官方数据源的长期可用性不由本次隔离测试证明。本轮未部署生产服务。
