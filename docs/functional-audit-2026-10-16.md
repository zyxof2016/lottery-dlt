# 大乐透功能核查 · 2026-10-16

此文记录1.0.2核查时的历史状态。1.1.0当前实现范围见 [七项优化与验收](optimization-1.1.0.md)。

此前交付没有完整移植 lottery-k8。七个页面入口和基础计算已经存在，但入口数量不能代表功能完整；此前验证只做过预览和分析，没有用浏览器验证实际保存至对奖的全过程。

## 实现范围

| 功能 | 实际状态 | 限制 |
|---|---|---|
| 单式、复式、胆拖 | 已实现 Rust 生成和组合展开 | 单组上限1000注；均衡策略仅单式 |
| 热号、冷号、遗漏 | 已实现历史排序与候选池抽号 | 启发式实验，不是校准后的预测模型 |
| 保存、刷新、复制、导出 | 已实现 SQLite 原票组保存、内容校验和 JSON 导出 | 无删除、恢复全部方案或用户账号隔离 |
| 官方开奖同步 | 已实现官方接口、分页及事务导入 | 定时器每30分钟只同步最近100期 |
| 网页开奖导入 | 支持 Draw 数组、draws 对象、官方 value.list JSON | CSV 使用 CLI；网页无文件选择器 |
| 对奖与奖金补充 | 按已保存票组计算逐注命中、奖级和金额 | 缺失奖额为待核实；不自动计算活动派奖、税或早期19019期以前奖金 |
| 每期推荐归档 | 手动固定5个预设；按期比较投入、中奖注数、奖金和净收益 | 不自动发布；不同预设预算不同，不能当作同预算策略排名 |
| 历史回测 | 单式逐期使用之前的开奖，输出轨迹 | 无复式、胆拖、自定义票组回测 |
| 参数／结构优化器 | **未实现** | 已移除“科学回测与优化”名称中的优化承诺 |
| 研究评估 | 五组单式策略在相同期数、相同预算上回放 | 无专家融合、消融、Top-K漏斗、校准、确认窗口和后台研究队列 |
| 自动推荐、自动冻结确认 | **未实现** | 当前服务不能宣称已经具备 lottery-k8 对应工作流 |
| 独立开奖前时间证明 | **未实现** | 截止时间由操作人填写，本机摘要和时钟不能提供独立证明 |

## 确认的问题与1.0.2修复

1. 推荐页和个人页原来直接复用全部记录。现为个人页显示个人保存，推荐页读取真实推荐及整期清单；个人票组被推荐清单复用时保留原始身份，不能靠改写 kind 伪造归档。
2. 同一期更改种子再归档原会产生另一组推荐。新增每期唯一且带摘要的 `recommendation_batches` 清单，首次事务保存后固定；再次操作返回首次票组，保留结算更新。
3. 热冷／遗漏单式原来把池大小暗中扩大到至少前12后6。现严格使用填写值，候选组合不足明确拒绝；回测固定前12后6并明确显示。
4. 原来不适用的形态参数仍可编辑，有些还会偷偷影响随机种子。网页禁用不适用参数，后端规范化这些值；复式／胆拖不接受名为“均衡覆盖”而实际随机选池的请求。
5. 模拟原来重新生成却不核对当前预览。现强制提交并核对 `preview_id`，配置或数据改变就拒绝模拟；页面也丢弃已失效的异步结果。
6. 导入页原先声称支持官方 JSON，但提交代码会拒绝。现网页和接口都实际调用官方解析器。
7. 令牌原来只写入会话存储，没有验证。现有实际认证接口、验证登录及退出；页面显式提示计算和写入需要管理员令牌。
8. 预览票组原来把保存操作放在内部滚动区域末尾。已移除该内部高度限制。

## 验证与数据边界

- Rust全目标31项测试：24项核心、6项API、1项离线覆盖实验；Clippy警告作为错误检查。
- 新增完整流程测试：生成→保存→重开数据库→改变主种子→导入隔离测试开奖→缺失奖金保持未知→补充奖额→按原票面结算→导出一致。
- 浏览器完整流程使用 `scripts/verify-workflow.py`：在线备份复制到临时数据库，单独监听127.0.0.1:6793，测试写入和合成开奖仅发生在该临时库，退出即删除。
- 生产验证脚本 `scripts/verify-deployment.py`、`scripts/verify-browser.py` 只预览和分析，不保存测试票组。
- 生产核查时实际方案数为0，没有实际推荐历史可复盘；不以历史回测轨迹填充真实推荐。

1.0.2的生成规则为 `dlt-plan-v2`。之前1.0.1的覆盖报告属于旧规则，新预览可能改变；已有方案仍使用保存的原始票面，不事后重建。
