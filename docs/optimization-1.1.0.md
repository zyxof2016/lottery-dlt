本次对应七项优化，后端及运维命令继续使用 Rust。入口仍为 `/dlt/`，生产目录 `/data/apps/lottery-dlt`。生成规则升级为 `dlt-plan-v3`，历史保存票面和审计记录不重建。

## 使用入口

- **方案生成**：已核实的期号和截止时间自动填写；追加/倍投只改变成本及奖金。
- **概率与历史回测**：选择完整投注形态，或点击“带入当前选号配置”。下方“固定预算结构优化”可运行优化并带入真实票组。
- **策略对照实验**：五组策略回放，以及多种子历史留出验证；结果保存在后台任务中。
- **系统设置**：官方日程、自动推荐窗口、同步状态、即时备份与恢复验证、任务历史和证据下载。

默认自动参考预设的总方案成本为88元；这是参考票组，不表示已经购票。自动任务不会下单、付款或对外发送消息。

## 数据与统计边界

官方接口目前主要返回已开奖期。推导日程明确标记为 `official_rules_calendar_checked_against_full_year`，不是伪装成下一期开奖公告。依据为：[官方销售时间公告](https://m.lottery.gov.cn/xxgk/tzggz/20221220/10027143.html)、[官方休市数据](https://webapi.sporttery.cn/gateway/lottery/getCloseTemplateV1.qry)及官方真实开奖历史；全年日期不吻合时停止推导，跨年等待明确日程或本年开奖，不自行补造期号。临时调整仍以官方公告为准。

结构覆盖评分为 `前区并集/35 + 后区并集/12 + 不同后区组合/66`，不等于中奖概率。见奖率按整组实际票组模拟，固定奖回本指标不含浮动奖、派奖、税，因此是完整回本概率的下界。选优和验证使用不同模拟样本；验证结果不用于再次改选。

研究按同期开奖聚合多个种子后计算配对差，避免把重复回放当作独立开奖样本。近似区间及p值仍有小样本和时间相关性限制。训练选择与后续历史留出验证分离；这不是未来预注册确认。专家融合、消融和未来确认协议没有在本次七项中实现，不能宣称大乐透已完整复制 lottery-k8 的高级研究功能。

备份恢复命令只写新路径，不能直接覆盖正在运行的生产数据库。真正切换至恢复库前须停止写入并核验路径；可用下列命令先生成恢复库：

```bash
./lottery-dlt --db /path/to/live.sqlite3 backup --out /path/to/new-backup.sqlite3
./lottery-dlt --db /path/to/live.sqlite3 restore --from /path/to/new-backup.sqlite3 --out /path/to/new-restored.sqlite3
```

生产的即时备份和每日备份存入 `/data/apps/lottery-dlt/backups`，恢复验证的临时库用后删除。手动备份和升级前备份不参与30天自动清理。

## 任务接口

`POST /api/jobs`，请求 `{ "kind": "backtest" | "optimize" | "research", "input": {...} }` 返回202及真实任务ID。`GET /api/jobs` 查询最近50个任务；`GET /api/jobs/{id}` 获取输入、历史摘要、状态和结果；`POST /api/jobs/{id}/cancel` 取消未结束任务。以上接口要求管理员令牌。任务保留提交时的历史及种子快照；服务重启后运行中任务标为中断，版本变化的排队任务不会用新规则静默继续。

42项Rust测试（24核心、7API、10优化、1离线覆盖实验），另有Clippy和JavaScript语法检查。`scripts/verify-optimizations.py` 在临时复制数据库和单独的127.0.0.1:6793服务上，实际执行保存、导入、复式/胆拖回测、优化结果带入、多种子留出研究、取消、备份恢复和分页；合成开奖只用于这个隔离库。
