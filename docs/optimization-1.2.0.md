# 1.2.0：参照 lottery-k8 的复盘与号码池分析

本轮对照本地 `lottery-k8` 的 `live-review.md`、`pool-intersection.md`、`coverage-budget.md` 和 `cross-pool-validation.md`，将适合大乐透双区规则的日常复盘和集合分析接入现有 Rust 项目。入口仍为“每期推荐与复盘”，也可直接访问 `/dlt/reviews#live-review` 和 `/dlt/reviews#pool-intersection`。未配置代理前缀时去掉 `/dlt`。

## 实际留档持续复盘

新增公开只读接口 `GET /api/recommendations/live-review?limit=30`，窗口允许1～120期。读取使用单一 SQLite 事务，包含整期清单、原始票组、开奖与日程，不重新生成号码。日期按北京时间核对。

清单和原始记录摘要损坏、清单引用丢失或身份不符时拒绝整份报告；HTTP返回409。实际时刻晚于截止、输入截止不早于目标期或截止日期与实际开奖日期不一致的记录单列排除原因。复盘核对本地留档完整性，尚无独立时间戳证明；旧版单独留档保留展示，但不进入整期成绩。

窗口包括已知日程与推荐，并补列开始跟踪之后已缓存开奖中的缺档。导入历史之前没有跟踪日程的期号不会冒充历史推荐。状态分为已结算、奖金待核实、待开奖、缺档、尚未留档和不纳入成绩；缺档与待开奖均不计零分。

成本分别统计已开奖与待开奖；存在未核实奖额时，累计完整奖金与净额为 `null`。另列奖额完整子集的方案数、成本和奖金，避免拿部分已知奖金减去全部成本。中奖方案数、不同中奖期数与中奖注数分别保留。前后区并集命中只描述覆盖，不代表同一注命中了全部号码。

策略对照只使用双方均存在合格已开奖记录的共同期，并逐期核对注数、追加、倍数与成本一致。报告保留共同期列表、左右原始方案ID、逐期差值和预算不匹配期号。没有共同期或奖金缺失时，相应金额差值为 `null`。相同预算下仍可能存在票组结构差异，结果只描述实际档案，不作为模型预测优势或显著性证据。

JSON导出含逐期状态、号码并集、命中、成本、核算摘要、生成规则版本及原始方案／清单摘要。报告自身的 `content_hash` 标识当前数据视图，读取时间不参与摘要；开奖或奖金补齐后视图自然更新。

## 前后区号码池交集

从实际推荐或个人方案读取完整原始票组，按区取并集形成池；支持分页、期号前缀筛选、跨期跨来源选择与手动输入。已选池保持到手动移除或清空，最多200池。

- 前区只接受1～35，后区只接受1～12。两区分别计算，号码互不混用。
- 手动池支持空格、逗号、顿号、分号和换行；非法号码整池拒绝；同池重复号码合并。
- 严格交集是全部所选池的共有号码。单池交集为其自身；无池不产生交集；交集为空时明确展示。
- 频次为包含某号的池数，频率为频次除以所选池数。按频次降序，同频号码升序；高频门槛可调。
- 相同原始来源ID不能重复计数。不同ID但两区内容相同的池仍分别计频，同时列出相同内容组，不能当作独立预测证据。
- 每号可查看包含及未包含它的池；JSON保存完整池、来源期号、保存时间和原始方案ID。
- 开奖标记只对照用户选择的一个当前期号。来自其他期的池单独提示，不混入它们原期的命中；无缓存时命中为未知。
- 选择及门槛存于当前标签页 `sessionStorage`；恢复或写入失败会显示提示，当前计算和导出仍可用。
- JSON与CSV始终导出全部并集行，不受显示门槛影响。CSV正确引用字段，并对可能触发表格公式的来源文字加文本前缀。

这些计算在浏览器中完成，不新增服务端常驻进程或生产运行依赖。分析不会改写推荐、个人方案或已核算原票组；手动池与交集导出不构成新发布推荐。

## 读取修复与兼容

修复推荐页先读取“同一期最近50条个人记录”再筛选的缺陷。同一期个人记录很多时，原推荐可能被挤出或错误报告缺少票组。现在在同一个事务中按清单完整读取推荐及被引用的个人方案，避免截断和混合快照；开奖记录按期去重返回。

版本升级为1.2.0，生成规则继续使用 `dlt-plan-v3`；无需迁移表结构。原始号码、摘要与存储格式保持兼容。

## 验证

```bash
cargo fmt --check
cargo test --locked --all-targets
cargo clippy --all-targets --locked -- -D warnings
node --check web/app.js
node --check web/pools.js
node --check web/reviews-ui.js
node tests/pools.cjs
node tests/review-ui.cjs
cargo build --release --locked
```

新增5项Rust检查覆盖：待开奖／缺档／未知奖金和奖额补齐、原票组及种子不变、共同期预算过滤、逾期／日期不符／单独归档排除、超过50条个人记录时推荐完整性、个人方案复用、带代理前缀的公开接口与损坏摘要409。7项集合检查覆盖双区交集、去重、同内容提示、非法输入、跨期命中和完整导出。

浏览器验收脚本会创建临时数据库并启动独立本机服务，所有合成数据只写入该临时库，不读取生产配置。需已有开发用Playwright及Chromium：

```bash
cargo build --locked
# PLAYWRIGHT_MODULE可指向已有playwright或playwright-core模块；无此变量时使用标准模块解析
node scripts/verify-k8-alignment.cjs --browser /path/to/chrome \
  --output test-results/k8-alignment
```

脚本检查7个桌面／手机页签、10个实际归档来源、跨期跨来源选择、手动错误输入、开奖及奖金补齐、JSON／CSV、刷新恢复、存储失败提示、只读操作前后数据库内容一致及页面脚本错误，输出JSON和截图。

本次本地已通过47项Rust全目标测试、7项集合测试、4项前端状态检查、Clippy、JavaScript语法检查及Release构建。前端状态检查在Node VM中验证会话恢复、损坏格式、存储失败提示、来源文字转义与空留档显示，不替代浏览器验收。当前执行沙箱禁止套接字：本机监听返回 `Operation not permitted`，Chromium也因 `setsockopt` 被禁止而退出。因此本轮浏览器脚本尚未完成运行，手机布局与真实浏览器交互仍待在允许启动服务和Chromium的环境中验收，未将旧版浏览器结果作为1.2.0证据。
