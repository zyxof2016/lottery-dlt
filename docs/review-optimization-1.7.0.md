# 1.7.0 复盘诊断优化

本轮先检查本地正式数据目录，再核对已有复盘实现，并参照本机 `lottery-k8/docs/review-20261027.md` 中的换入／换出及来源重叠检查。`data/` 当前只有 `.gitkeep`，因此本轮没有可用于真实成绩复盘的大乐透留档；不报告实际命中率、奖金或预测改进。下面的截图及示例均来自临时数据库中的合成测试档案。

已有预算增量功能能够展示逐期新增和丢弃号码，但缺少同预算共同期的净变化汇总，以及来源集合相似程度。本轮在原始留档上补充只读诊断，保留选号策略、原票组、评分证据、对奖规则及原有统计。

## 同预算换号复盘

“每期推荐与复盘”新增“换号复盘”入口，可查看当前期和窗口内逐期原票：

- 前后区分别展示换入、换出号码，以及补回命中、丢失命中和净变化。净变化为补回减丢失，前区和后区不混加，负值保留。
- 汇总仅纳入双方同一期、合格的实际整期档案，且金额、注数、追加、倍数相同。方向由成本、注数、原名称和编号固定，差值为对照方案减原方案，不按开奖结果选优。
- 汇总再按预算参数及双方前后区并集号数分别分组；相同名称在不同池大小下的结果不混为同一平均值。记录共同已开奖／待开奖期、累计补回／丢失／净增、每区优／平／劣期数、完整净额差及奖额完整子集。
- 两区号数均相同时才标为“两区同号数”；仅预算一致、池大小不同会明确列出各区变化。当前预设中的两种6注复式同为12元，但前后区分别为5／4和6／2，不能称为等容量换号。
- 没有共同已开奖期时净变化为未知；待开奖不计零分。缺失任一期奖额时完整净额差为未知，同时单列已知金额子集及期数。命中净变化与奖金差分别核算。

原票链接保留期号和方案编号；逐期轨迹保留整期摘要、原评分摘要、数据截止和原票组身份。诊断不会把两池相加生成新推荐，也不改已保存号码池。

## 原始来源池重叠

新增“来源重叠”入口，与换号区域共用当前期选择。默认选择窗口内最近一个有合格来源的已开奖期；可主动切换到待开奖期查看原池相似度。选择期号不会改写档案，刷新对奖后仍保留有效选择。

每区分别给出原池号数、完整共同号码、交集和并集数量、Jaccard比例、固定大小均匀池的期望交集，以及号码入选指示相关性。设全区大小为 `N`、两池大小为 `a,b`、交集数量为 `i`：

- 前区使用 `N=35`，后区使用 `N=12`。
- Jaccard为 `i/(a+b-i)`；均匀固定大小池的期望交集为 `a*b/N`。
- 入选指示相关性为 `(N*i-a*b)/sqrt(a*(N-a)*b*(N-b))`，支持两池大小不同。
- 任一池覆盖全区时没有入选指示方差，相关性返回未知，显示“不可计算”，不伪造0。

这些值描述当期集合相似度，不代表跨期预测相关性、模型独立性或有效独立来源数量。原评分的确认等分、未使用历史评分和旧档评分未记录分别显示；相同两区池与相同完整票组也分别标注。不同预算可查看重叠，但列出未进入同预算汇总的原因，不计算其同预算净增。

## 无已开奖样本时不显示零收益

原复盘聚合在空样本下使用“已开奖数等于奖额完整数”的条件，因两者均为0而返回零奖金和零净收益。现在必须至少有一个已开奖样本才能认定完整金额；空库或只有待开奖的窗口返回未知。

新增换号汇总也遵循此规则。原先已有的中奖注数、成本和实际已开奖结果不受影响。

![窗口只保留待开奖期时，命中变化和收益均不伪装成0](../test-results/replacements-1.7.0/05-pending-window-desktop.png)

## 兼容与验证

版本1.7.0继续使用 `dlt-plan-v3`，无需数据库迁移。`Plan`、`SavedPlan`、原档案摘要及原评分保持不变。完整数据导出仍为版本4，号码池导出仍为版本3；复盘报告版本2仅增加 `replacement_review` 和逐期 `source_comparisons` 字段。旧版复盘响应缺少新字段时，前端保留原功能，不显示不存在的新区域。

“导出替换与重叠证据”导出版本1的诊断JSON，包含当前完整复盘摘要、窗口内全部逐期来源及换号汇总，不受当前显示期号限制。

验证结果：67项Rust全目标测试、41项JavaScript检查、Clippy、格式检查及Release构建通过。

- 数学测试覆盖前后区不同总体大小、等容量换号、补回减丢失恒等式、负净变化、完整票组与号码并集的区别、全区相关性不可计算、不同财务设置及不同期号拒绝、不同池大小分别汇总、待开奖和缺失金额。
- 归档集成测试使用两期已开奖和一期待开奖的临时历史档案，核对累计净变化与原预算对照；改变当前种子不改变报告，读取前后原票、评分、配置、开奖、推荐及审计数保持一致。排除的档案不会进入来源对照。
- `scripts/verify-replacements.cjs` 使用发布二进制和临时数据库，实际创建三期原始预设，其中一期模拟开奖、两期待开奖；每期10组来源对照中，1组预算一致，另9组不进入同预算汇总。检查负的后区净变化、窗口／期号切换、完整JSON下载、奖金缺失和补齐、原池几何不变、手机局部滚动及无页面溢出。
- 继续运行 `verify-usability.cjs`、`verify-applicability.cjs`、`verify-k8-alignment.cjs`、`verify-score-evidence.cjs`，回归生成／保存／查票、草稿与故障恢复、预算增量、集合诊断、原评分、稳定性及奖金补齐。
